## 1. Phương pháp & Tiêu chí phân loại

Mỗi năng lực (Capability) của Provider được phân loại theo 5 cấp độ nghiêm ngặt:
- `supported`: Đã xác minh có CLI/API/SDK chính thức hỗ trợ trực tiếp và an toàn từ môi trường Node.js/Electron.
- `partially_supported`: Đã xác minh có công cụ nhưng chỉ hỗ trợ một phần (ví dụ CLI có thể thực thi nhưng không phát streaming event chuẩn hóa hoặc thiếu cờ giới hạn workspace).
- `unsupported`: Nhà cung cấp không công bố hoặc không có giao diện điều khiển lập trình bên ngoài được xác minh.
- `unknown`: Chưa đủ tài liệu hoặc chưa có công cụ công khai để kiểm chứng độc lập.
- `manual_only`: Không có giao diện tự động hóa từ bên ngoài Studio; Owner cần thao tác trực tiếp trên giao diện của công cụ đó (ví dụ VS Code chat).

## 2. Kết quả Khảo sát Thực tế trên Môi trường Local (`2026-10-31`)

### 2.1 Google Antigravity / Gemini
- **Hiện trạng trên máy:**
  - Hoạt động trong vai trò **VS Code Extension** chính (`Google Antigravity` / Gemini Code Assist).
  - Thư mục dữ liệu: `C:\Users\Asus of Kien\.gemini\antigravity`.
  - Kiểm tra PATH: Lệnh `where.exe agy antigravity` $\rightarrow$ Không có binary CLI nào được cài vào PATH hệ thống.
  - Kiểm tra cổng mạng/IPC: Antigravity Extension giao tiếp nội bộ trong tiến trình Extension Host của VS Code qua vscode language server/extension protocol, không mở local socket hoặc HTTP port công khai để ứng dụng thứ ba (như Electron Desktop) gửi lệnh chạy ngầm.
- **Đánh giá kiến trúc:**
  - Tuyệt đối không giả lập một endpoint REST API hoặc daemon giả.
  - Đánh dấu trạng thái Adapter: `manual_only` / `ide-companion`.
  - Mọi yêu cầu sinh mã phức tạp từ Antigravity cần được Owner khởi tạo trực tiếp trong VS Code hoặc qua quy trình giao việc có kiểm soát.

### 2.2 OpenAI Codex (`codex-cli`)
- **Hiện trạng trên máy:**
  - Đã cài đặt tại: `C:\Users\Asus of Kien\AppData\Roaming\npm\codex.cmd`.
  - Phiên bản xác minh thực tế qua command-line: `codex-cli 0.159.2`.
  - CLI hỗ trợ cấu hình thư mục làm việc, truyền prompt, hỗ trợ quản lý model (`gpt-4.1`, `codex-mini-latest`) và tham số reasoning.
  - Authentication: Hỗ trợ kiểm tra trạng thái xác thực (`codex auth status`) và đăng nhập thông qua API key vault hoặc OAuth PKCE flow.
- **Đánh giá kiến trúc:**
  - Trạng thái Adapter: `partially_supported` / `restricted`.
  - Có thể khởi chạy qua `ProcessRunner` ở chế độ giới hạn (`restricted mode` hoặc `staging workspace`), thu thập stdout/stderr và mã thoát (exit code).
  - Giới hạn: CLI không có cơ chế kernel sandbox riêng; nếu chạy với quyền của người dùng hiện tại thì nó có thể đọc/ghi các file mà người dùng có quyền. Do đó buộc phải kết hợp với `WindowsPathGuard`, `RuntimeLockManager` và chế độ Staging/Approval.

### 2.3 Anthropic Claude / Claude Code
- **Hiện trạng trên máy:**
  - Kiểm tra lệnh `claude` (Claude Code CLI): `where.exe claude` $\rightarrow$ Không tìm thấy (chưa cài đặt CLI).
  - Có ứng dụng `claude-desktop.exe` tại `C:\Users\Asus of Kien\AppData\Local\Microsoft\WindowsApps\claude-desktop.exe`. Đây là ứng dụng GUI desktop độc lập dành cho người dùng cuối, không phải CLI tự động hóa cho Developer.
- **Đánh giá kiến trúc:**
  - Trạng thái Adapter: `not_installed` / `runtime_unavailable`.
  - Studio hiển thị trung thực là `not_installed` kèm hướng dẫn cài đặt `npm install -g @anthropic-ai/claude-code` khi Owner muốn kích hoạt trong tương lai. Không giả lập trạng thái sẵn sàng.

## 4. Kết luận & Hướng tiếp cận Adapter trong G2.6

1. **`AntigravityAdapter`:** Báo cáo trung thực vai trò `ide-companion` / `manual_only`. Không khởi chạy tiến trình CLI giả. Cung cấp chỉ dẫn rõ ràng cho Owner khi gán Task cho Antigravity.
2. **`CodexAdapter`:** Khởi chạy bằng `codex.cmd` qua `ProcessRunner`, truyền danh sách đối số an toàn, áp dụng timeout, giới hạn kích thước buffer stdout/stderr, chạy trong Staging Workspace hoặc chế độ `restricted` có Owner Approval.
3. **`ClaudeAdapter`:** Báo cáo trạng thái `not_installed`. Sẵn sàng cấu trúc adapter để khi Owner cài đặt `claude` CLI thì hệ thống tự động nhận diện mà không cần sửa code.
4. **`MockTestAdapter`:** Chỉ sử dụng duy nhất trong automated unit tests nội bộ với tag rõ ràng `test_mock`. Tuyệt đối không đăng ký vào production registry và không hiển thị trên Dashboard.
