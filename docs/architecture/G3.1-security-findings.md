**Dự án:** Personal AI Studio (`C:\AI-Studio`)  
**Phân loại:** Tài liệu Kiến trúc An ninh Bảo mật (Security Architecture)  
**Tác giả:** Senior Security Engineer / QA Automation  
**Ngày phê duyệt:** 31/10/2026  

---

## 1. TỔNG QUAN RANH GIỚI BẢO MẬT (SECURITY BOUNDARIES)

Personal AI Studio là ứng dụng Desktop vận hành theo mô hình **Owner-Only** (Chủ sở hữu duy nhất) trên hệ điều hành Windows 11. Các ranh giới an ninh trong hệ thống bao gồm:
1. **Ranh giới IPC Main <-> Renderer:** Ngăn chặn mã độc trong Web context hoặc trang web bên ngoài tương tác với Main Process.
2. **Ranh giới Bảo vệ Bí mật (Secret Protection Boundary):** Bảo đảm không bao giờ ghi plaintext credentials (API key, OAuth token, mật khẩu) vào SQLite, logs, hay Telemetry stream.
3. **Ranh giới Hệ thống tệp Windows (Windows Filesystem Boundary):** Ngăn chặn vượt rào đường dẫn (Directory Traversal), ký tự điều khiển NTFS (ADS), tên thiết bị DOS, và các kỹ thuật lách cơ chế so sánh Win32.
4. **Ranh giới Vai trò Đa tác nhân (Multi-Agent Role Boundary):** Ràng buộc đặc quyền theo đúng vai trò được gán (Primary, Worker, Reviewer, Observer).
5. **Ranh giới Phê duyệt Hành động Nhạy cảm (Approval Gate):** Cơ chế phê duyệt nguyên tử chống tái sử dụng (Anti-Replay) và chống chạy quá hạn (Expired Request Gate).

## 2. IPC ORIGIN VALIDATION & FRAME ISOLATION

### Điểm yếu phát hiện:
Trong kiến trúc Electron, bộ lắng nghe IPC (`ipcMain.handle`) cần xác thực người gửi (`event.senderFrame`). Kiểm tra trước đây sử dụng:
```typescript
// KHÔNG AN TOÀN: Dễ bị lách qua các domain tương đồng
if (frameUrl.startsWith('http://localhost:5173')) { ... }
```
Cách kiểm tra này chấp nhận cả các URL độc hại như `http://localhost:5173.evil-domain.com` hoặc các cổng khác nhau nếu kẻ tấn công tạo môi trường giả lập.

### Cơ chế gia cố tại G3.1:
Trong `src/main/ipc/registerIpcHandlers.ts`, hàm `verifyTrustedSender` được nâng cấp sử dụng bộ phân tích URL chuẩn (`new URL(frameUrl)`):
```typescript
let parsed: URL;
try {
  parsed = new URL(frameUrl);
} catch {
  return false;
}

if (parsed.protocol === 'http:' || parsed.protocol === 'ws:') {
  const isLocalHost = parsed.hostname === 'localhost' || parsed.hostname === '127.0.0.1';
  const isViteDevPort = parsed.port === '5173';
  return isLocalHost && isViteDevPort;
}

if (parsed.protocol === 'file:') {
  const normalizedPath = path.normalize(fileURLToPath(frameUrl));
  const rendererDist = path.normalize(path.resolve(__dirname, '../../renderer'));
  return normalizedPath.startsWith(rendererDist);
}
```
**Kết quả:** Toàn bộ các yêu cầu từ iframe không mong muốn, port sai lệch, hoặc origin từ internet đều bị loại bỏ ngay tại lớp cửa ngõ IPC.

## 3. TELEMETRY REDACTION & CREDENTIAL MASKING

### Điểm yếu phát hiện:
Hệ thống Telemetry thu thập stdout/stderr từ các Runtime session (Node.js CLI, Python, Unity process). Một số thư viện của bên thứ ba (Google Cloud Client, GitHub CLI, curl) in token ra màn hình dưới dạng:
- `ya29.a0AfH6SMB...` (Google OAuth 2.0 Access Token)
- `github_pat_11ABCD...` (GitHub Fine-grained Personal Access Token)
- `Authorization: Basic dXNlcjpwYXNz` (Basic Auth Base64)
- `https://admin:password123@api.com` (Inline URL Credentials)

### Cơ chế gia cố tại G3.1:
Trong `src/services/telemetry/TelemetryRedactor.ts`, các biểu thức Regex được chuẩn hóa và bổ sung:
```typescript
// Google OAuth Access Token
/(?:ya29\.[A-Za-z0-9_-]{20,})/g,
// GitHub Fine-grained PAT
/(?:github_pat_[A-Za-z0-9_]{22,})/g,
// Basic Authentication Header
/(?:Authorization\s*:\s*)?Basic\s+[A-Za-z0-9+/=]{8,}/gi,
// Mật khẩu nhúng trong URL
/:\/\/[^:\s]+:[^@\s]+@/g
```
Tất cả các chuỗi nhạy cảm trên đều được thay thế bằng các nhãn che mặt nạ tương ứng trước khi phát tán qua Event Broker hoặc ghi vào bảng `runtime_events` trong SQLite.

## 4. WINDOWS PATH GUARD & WIN32 EVASION VULNERABILITIES

Hệ điều hành Windows có nhiều đặc thù về phân giải đường dẫn tệp (Win32 API Path Normalization) mà các hệ điều hành POSIX không có:

### Các kỹ thuật tấn công và giải pháp ngăn chặn:
1. **Trailing Dots / Spaces Evasion:**  
   Win32 tự động cắt bỏ dấu chấm và dấu cách ở cuối tên tệp (ví dụ: `secret.cs.` được mở thành `secret.cs`). Kẻ tấn công có thể dùng `secret.cs.` để lách qua danh sách đen cấm sửa `secret.cs`.  
   *Giải pháp:* `WindowsPathGuard.ts` tách từng segment của đường dẫn trước khi trim và kiểm tra: `if (seg.endsWith('.') || seg.endsWith(' ')) return { valid: false, traversalOrLinkEscapeDetected: true };`.
2. **Drive-Relative Paths (`C:file.txt`):**  
   Đường dẫn có ký tự ổ đĩa nhưng không có gạch chéo (`C:temp.txt`) sẽ trỏ vào thư mục hiện tại của ổ C, thay vì root `C:\`. Điều này dẫn đến việc thoát khỏi Workspace mà không dùng `..\`.  
   *Giải pháp:* Thêm regex `/^[a-zA-Z]:[^\\/]/.test(trimmedTarget)` và từ chối ngay lập tức.
3. **NTFS Alternate Data Streams (`file.txt:hidden`):**  
   Dùng để lưu trữ payload độc hại bên trong luồng dữ liệu ẩn mà không thay đổi kích thước file hiển thị.  
   *Giải pháp:* Quét ký tự hai chấm `:` sau ổ đĩa gốc, từ chối toàn bộ ADS.
4. **DOS Device Names (`CON`, `PRN`, `AUX`, `NUL`, `COM1..9`, `LPT1..9`):**  
   Truy cập các file này trong Windows sẽ làm treo tiến trình do đợi tín hiệu phần cứng.  
   *Giải pháp:* Regex kiểm tra danh sách bảo lưu trên mọi phân đoạn đường dẫn.
5. **Unicode Normalization Bypass:**  
   Tên tệp Unicode ở dạng Decomposed (ví dụ chữ `é` tạo bởi `e` + dấu sắc `\u0301`) có thể lách qua so sánh chuỗi nhị phân với tệp dạng Composed (`\u00E9`).  
   *Giải pháp:* Gọi `rawTarget.normalize('NFC')` ngay từ đầu hàm phân giải.

## 5. MULTI-AGENT ROLE PRIVILEGE BOUNDARY

Trong kiến trúc Multi-Agent của Personal AI Studio:
- **Primary Agent:** Có quyền lập kế hoạch, phân rã công việc, và hoàn thành phiên làm việc.
- **Worker Agent:** Có quyền đọc các nhiệm vụ được giao, tạo mã nguồn và tệp artifact trong workspace. Không có quyền tự chuyển trạng thái phiên sang `completed` hay `reviewing`.
- **Reviewer Agent:** Có quyền kiểm tra artifact, phê duyệt hoặc yêu cầu sửa đổi (revision). Áp dụng nghiêm ngặt quy tắc **Anti-Self-Review** (tác giả không được tự review sản phẩm của mình).
- **Observer Agent:** Chỉ có quyền đọc (Read-only monitor).

### Cơ chế gia cố tại G3.1:
Trong `MultiAgentOrchestrator.ts`:
- Bắt buộc kiểm tra danh sách thành viên phiên (`collaboration_members`). Agent bên ngoài không thể can thiệp.
- Chặn đứng Observer Agent: Nếu `member.role === 'observer'`, mọi nỗ lực gọi `transitionState` đều bị từ chối với lỗi bảo mật cấp cao.
- Chặn đứng Worker Agent: Ngăn chặn Worker Agent tự đóng phiên hoặc tự chuyển trạng thái tổng thể.

## 6. PLAINTEXT SECRET PROTECTION

Hệ thống tuân thủ nghiêm ngặt quy tắc Zero Plaintext Secret trong cơ sở dữ liệu:
- Mọi tài khoản (`accounts`) chỉ lưu `credential_ref` có tiền tố an toàn: `wincred://` (Windows Credential Manager) hoặc `vault://` (Internal Secure Storage).
- `AccountService.ts` từ chối ngay lập tức nếu `credentialRef` chứa chuỗi dạng API Key thô (như `sk-...`, `AIza...`, `ghp_...`).
- Không có bất kỳ API nào cho phép Renderer đọc ngược khóa bí mật dạng plaintext từ SQLite.
